# System Design - Library Management System

**Version**: 1.0  
**Date**: March 2026  



## 1. System Overview

The Library Management System is a monolithic full-stack web application with:
- **Frontend**: Static HTML/CSS/JS served via a web server or Live Server
- **Backend**: Spring Boot REST API
- **Database**: MySQL RDBMS
- **Auth**: JWT-based stateless authentication

### 3.2 Class Design — Backend

#### Model Layer
```java
// Book.java
@Entity
public class Book {
    @Id @GeneratedValue
    private Long id;
    private String title;
    private String author;
    private String isbn;
    private String category;
    private int totalCopies;
    private int availableCopies;
    private int publishedYear;
}

// Member.java
@Entity
public class Member {
    @Id @GeneratedValue
    private Long id;
    private String name;
    private String email;
    private String phone;
    private String address;
    private MemberStatus status;   // ACTIVE | INACTIVE
    private LocalDate joinedDate;
}

// Loan.java
@Entity
public class Loan {
    @Id @GeneratedValue
    private Long id;
    @ManyToOne private Book book;
    @ManyToOne private Member member;
    private LocalDate issueDate;
    private LocalDate dueDate;
    private LocalDate returnDate;
    private BigDecimal fineAmount;
    private LoanStatus status;   // ACTIVE | RETURNED | OVERDUE
}

// User.java
@Entity
public class User {
    @Id @GeneratedValue
    private Long id;
    private String username;
    private String password;    // BCrypt
    private String email;
    private Role role;          // ADMIN | LIBRARIAN | MEMBER
}
```

#### Service Layer — Key Logic
```java
// LoanService.java — Issue Book Logic
public Loan issueBook(Long bookId, Long memberId) {
    Book book = bookRepo.findById(bookId).orElseThrow();
    if (book.getAvailableCopies() <= 0) throw new BookNotAvailableException();
    Member member = memberRepo.findById(memberId).orElseThrow();

    Loan loan = new Loan();
    loan.setBook(book);
    loan.setMember(member);
    loan.setIssueDate(LocalDate.now());
    loan.setDueDate(LocalDate.now().plusDays(14));
    loan.setStatus(LoanStatus.ACTIVE);

    book.setAvailableCopies(book.getAvailableCopies() - 1);
    bookRepo.save(book);
    return loanRepo.save(loan);
}

// LoanService.java — Return Book + Fine Calculation
public Loan returnBook(Long loanId) {
    Loan loan = loanRepo.findById(loanId).orElseThrow();
    LocalDate today = LocalDate.now();
    loan.setReturnDate(today);

    if (today.isAfter(loan.getDueDate())) {
        long daysLate = ChronoUnit.DAYS.between(loan.getDueDate(), today);
        loan.setFineAmount(BigDecimal.valueOf(daysLate * 5)); // ₹5/day
    }

    loan.setStatus(LoanStatus.RETURNED);
    Book book = loan.getBook();
    book.setAvailableCopies(book.getAvailableCopies() + 1);
    bookRepo.save(book);
    return loanRepo.save(loan);
}

## 5. Security Design

### JWT Flow
```
1. User POSTs credentials → /api/auth/login
2. Spring Security authenticates username/password
3. JwtUtil generates token with role + expiry (24 hrs)
4. Token returned to client → stored in localStorage
5. Client sends token in every request header:
   Authorization: Bearer <token>
6. JwtFilter intercepts every request:
   - Validates token signature
   - Extracts username + role
   - Sets SecurityContext
7. @PreAuthorize checks role before controller executes
```

### Role Permissions Matrix

| Endpoint | ADMIN | LIBRARIAN | MEMBER |
|----------|-------|-----------|--------|
| POST /auth/register | ✅ | ❌ | ❌ |
| POST /books | ✅ | ✅ | ❌ |
| PUT /books/{id} | ✅ | ✅ | ❌ |
| DELETE /books/{id} | ✅ | ❌ | ❌ |

| GET /loans/my | ✅ | ✅ | ✅ |
| GET /dashboard/stats | ✅ | ✅ | ❌ |

## 6. Frontend Design

### Page Flow
```
index.html (Login)
     │
     ▼ (JWT stored in localStorage)
dashboard.html
     ├──► books.html        (Search, Add, Edit, Delete Books)
     ├──► members.html      (Search, Add, Edit, Delete Members)
     └──► loans.html        (Issue, Return, View Loans)
```

### JS Module Responsibilities

| File | Responsibility |
|------|---------------|
| `auth.js` | Login form, JWT storage, logout |
| `api.js` | Base fetch wrapper with auth header |
| `books.js` | Book CRUD, search, table rendering |
| `members.js` | Member CRUD, search, table rendering |
| `loans.js` | Issue/return, loan table, fine display |
| `dashboard.js` | Stats fetching, card rendering |

## 7. Error Handling Strategy

### Backend
- Global `@ControllerAdvice` for consistent error responses
- Standard error response format:
```json
{
  "status": 404,
  "error": "Not Found",
  "message": "Book with ID 5 not found",
  "timestamp": "2026-03-23T10:30:00"
}
```

### Frontend
- All fetch calls wrapped in try/catch
- Toast/alert notifications for success and error
- 401 responses redirect to login page
